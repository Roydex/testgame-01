# 美术圣经（ART BIBLE）

> 状态：阶段 1 文档补写（2026-11-19）。这是**美术方向草案，待用户确认**。当前游戏内全部为程序化占位几何体，正式美术在阶段 7 制作。
> 规范来源：AGENT.md §2（机甲设定）、§6（打击感与美术规范）。

## 1. 总体风格

- **基调**：写实偏风格化的硬表面机甲。不是动漫的夸张比例，也不是军事写实的灰绿色调。每台机甲都像来自不同文明的“工艺品”，通过结构逻辑和材质讲述背景。
- **四台机甲必须一眼可辨**：剪影优先于配色。即使把画面变成黑白或缩小到 64 px，也能分清是哪一台。
- **结构可信**：关节、液压、推进器、动力传递要有机械逻辑；武器挂载点要能看出来自哪里、怎么发力。
- **重量感**：轻型机体（白祷）动作快、停顿短；重型机体（赤狱、苍藓）启动和停止都有惯性，落地有冲击。动作表现要与 MovementProfile 的手感一致。
- **可读性高于华丽**：特效再好看，也不能遮住预兆、遮住目标或妨碍判断。

## 2. 机甲

### 01 白祷·零式（PALE SERAPH）

| 项目 | 方向 |
|---|---|
| 剪影 | 修长人形，头身比偏高；背后两片光翼和头顶**残缺的冠冕**构成独有的轮廓 |
| 比例 | 四台中最纤细；四肢细长，关节处有悬浮分离的装甲片 |
| 材质 | 珍珠白陶瓷质感的装甲；关节缝隙透出暖白色光；局部有古老的磨损和裂纹（圣骸感） |
| 配色 | 主色珍珠白、象牙白；能量色暖金白；点缀淡金色 |
| 动作风格 | 轻快、精准；出招前摇短，收招干净；招架是“以静制动”的瞬间动作 |
| 特效语言 | 光矛的拖尾是细长的白金色光带；招架与折射时镜盾闪出白光；大招时冠冕补完、光翼展开，整体泛金 |

### 02 赤狱·断牙（HELLFANG）

| 项目 | 方向 |
|---|---|
| 剪影 | 明显非对称：一侧巨型动力爪，一侧链斧；背部排气管高高竖起 |
| 比例 | 上身宽厚、下身粗短，重心低，像一头蓄势的猛兽 |
| 材质 | 粗糙的焊接钢板和铆钉；裸露的液压管线；熔炉核心处有高温烧蚀的痕迹 |
| 配色 | 主色黑铁、暗红；能量色熔岩橙红；热量越高，装甲缝隙的发光越亮 |
| 动作风格 | 沉重、爆发；前摇带明显的蓄力后拉，命中时停顿感强；打空时有踉跄 |
| 特效语言 | 火星、热浪扭曲、排气管喷火；钩爪的锁链清晰可见；过热时冒出大量白色蒸汽（破绽信号） |

### 03 苍藓·方舟（VERDANT ARK）

| 项目 | 方向 |
|---|---|
| 剪影 | 宽大的龟甲背壳，几乎呈半圆形；部署时背甲展开，轮廓明显变化 |
| 比例 | 四台中最矮最宽；四肢粗短，像移动的堡垒 |
| 材质 | 生物与机械的混合：硬质甲壳加有机质感的菌丝管路，表面有苔藓状的生长纹理 |
| 配色 | 主色深苔绿、树皮褐；能量色生物荧光青绿；炮台与本体同色系 |
| 动作风格 | 缓慢、稳定；转身有“扎根”感；部署动作像播种，炮台从地面“长出来” |
| 特效语言 | 孢子颗粒、菌丝蔓延；束缚区地面有清晰的发光网纹；大招栖地是向外扩散的绿色菌丝 |

### 04 苍穹·星标（AZURE ORACLE）

| 项目 | 方向 |
|---|---|
| 剪影 | 细长的反关节腿、单侧巨型轨道炮；身边环绕几个浮动的观测阵列单元 |
| 比例 | 腿长、躯干窄，整体偏高；轨道炮比机体本身还长 |
| 材质 | 抛光的蓝色金属和碳纤维；整洁的军工质感，几乎没有磨损；观测阵列是半透明的光学元件 |
| 配色 | 主色深空蓝、银灰；能量色冷青蓝；轨道打击的光圈和光柱用危险色（见 §4） |
| 动作风格 | 精确、克制；蓄力时身体压低、稳定；射击后坐力明显，后摇时有可见的散热动作 |
| 特效语言 | 瞄准激光是细而直的青色光线；标记是悬浮在目标身上的几何坐标图标；轨道激光从天而降，有地面光圈预兆 |

## 3. 地图美术方向（阶段 6）

| 地图 | 方向 | 光照与天气 | 可读性要点 |
|---|---|---|---|
| A 坠星祭坛 | 古代环形遗址、陨石坑、断裂的巨柱，石材与星陨金属混合 | 黄昏斜阳，长影；天空中有坠星的余迹 | 开阔区域要有足够的地面参照物，方便判断速度和高度；巨柱破坏前后的轮廓差异要明显 |
| B 熔渊炼厂 | 重工业设施、冷却塔、管道、熔炉 | 内部熔岩发出的橙红色光与冷色工业灯对比 | 危险区域（高温地面、蒸汽）必须有清楚的颜色和图案标识；多层平台的边缘要醒目，避免误判落点 |
| C 雨蚀穹城 | 未来城市上层的屋顶、高架、连接桥，被暴雨侵蚀 | 暴雨、夜色、霓虹反光；地面湿润反射 | 雨和雾不能遮住机体和预兆；可坍塌的桥要有可见的裂缝预兆；远景的霓虹不能使用预兆色 |

通用规则：
- 地面和墙面要有可读的尺度参照，正式地图中保留灰盒网格的“可读”精神，但以美术方式呈现。
- 飞行天花板要有视觉提示，例如云层、空气扰动或界限光幕，不能只是一堵透明墙。

## 4. 全局颜色语言（强制）

这套颜色只用于表达游戏状态，**场景和装饰不得大面积使用这些颜色**，以免与状态信号混淆。

| 颜色 | 含义 | 现有占位实现 |
|---|---|---|
| **红 / 橙红** | 攻击预兆、危险区域、即将到来的伤害（前摇发光、轨道打击光圈） | 前摇时装甲发出脉动的红色光；测试靶开火前闪红 |
| **白** | 招架、折射（镜盾闪光、“招架 / 折射”文字） | 招架成功时镜盾闪白光，折射弹变为白蓝色 |
| **蓝** | 格挡（格挡成功的火花、减伤数字） | 格挡火花和伤害数字为浅蓝色 |
| **金** | 大招、审判状态、冠冕（大招就绪、生效） | 冠冕与光翼的金白色发光，HUD 的审判提示 |
| 橙黄 | 破防、反击加成（“破防”文字、×1.5 反击数字） | 破防火花为橙色，反击伤害数字为金黄色 |
| 绿 | 玩家 HP、己方友好信息 | HUD 的 HP 条 |
| 青蓝 | EN | HUD 的 EN 条 |

色盲友好：每个状态都必须**同时**用颜色以外的方式表达（形状、图标、文字、动作或音效）。例如预兆除了变红，还有动作上的蓄力和音效；招架除了变白，还有“招架”文字和清脆的金属声。

## 5. 可读性规则

1. **预兆永远可见**：任何重大攻击的预兆，不能被其他特效、粒子、雨雾或镜头遮挡。锁定镜头必须同时呈现玩家和目标（CameraRig 已有近距离取景和遮挡处理）。
2. **命中可确认**：命中、格挡、招架、破防四种结果，在 0.2 s 内就要能从画面和声音上分辨出来。
3. **特效不遮目标**：命中特效的持续时间要短（约 0.3 s 以内），大小不能完全挡住目标机体。
4. **镜头克制**：震屏和 FOV 冲击都有上限；不靠过长硬直或过度震屏制造“力量感”（AGENT.md §6）。
5. **剪影优先**：在远距离和混战中，靠剪影分辨机体，而不是靠颜色。
6. **离屏信息**：离屏敌人提示要能显示方向、距离和高度方向，颜色遵守 §4。

## 6. UI 风格

- **方向**：简洁的军用 HUD。半透明深色底，细线框，信息分层：核心信息（HP、EN、大招状态）在屏幕下方中央，目标信息在上方中央，提示文字在中央偏上。
- **字体**：当前使用系统自带的中文字体（UiFont 运行时挑选，项目中不放字体文件）。正式版如需引入字体文件，必须使用可商用且允许嵌入的开源字体（例如 SIL OFL 授权的字体），并记录在 §8 的资源清单中。
- **动效**：状态变化（例如大招就绪）用短促的动效强调，不用长时间闪烁。
- **调试面板（F1）**：保持纯文本，不做美化；正式版默认隐藏。

## 7. 占位资源政策与替换计划

**当前状态（2026-11-19）**：游戏内所有视觉和声音资源都是代码生成的，没有任何第三方资源文件。

| 类别 | 当前占位 | 替换阶段 |
|---|---|---|
| 机甲模型 | BoxMesh 拼装的方块机体（`MechVisual`）；四台机体目前共用同一个占位骨架 | 阶段 7 |
| 机甲动作 | 程序化关键姿势插值（`MechVisual` 的姿势曲线） | 阶段 7（正式动画） |
| 武器 / 特效 | 程序化方块和球体、TorusMesh 冲击环、ImmediateMesh 拖尾 | 阶段 7 |
| 场景 | 代码生成的灰盒（`GrayboxBuilder`），自写的网格 shader（`shaders/graybox_grid.gdshader`） | 阶段 6（正式地图）、阶段 7（美术） |
| 天空 / 光照 | 引擎内置的 ProceduralSkyMaterial 和 DirectionalLight3D | 阶段 7 |
| 音效 | 运行时用正弦波和滤波噪声合成（`ProceduralAudio`） | 阶段 7 |
| 字体 | 操作系统自带字体（`UiFont`） | 阶段 7 视需要评估 |

**原则**：占位资源**不能视为最终完成**（AGENT.md §6）。在阶段 7 验收前，ROADMAP 和 KNOWN_ISSUES 中都要保留“美术为占位”的记录。

## 8. 资源来源与许可证规则

1. **禁止复制受版权保护的机甲设计或游戏资源**，包括但不限于：现有动画、游戏、模型作品中可辨认的机体外形、标志性配色组合、特定武器设计、Logo 和 UI。参考图只能用于学习结构和材质，不能描摹或拼接。
2. **允许的来源**：
   - 自制资源。
   - 明确允许商用和修改的开源或免费资源，例如 CC0 或 CC-BY（需署名）授权的资源。
   - 已购买并取得相应授权的资源。
3. **每一个外部资源都必须登记**：来源链接、作者、许可证类型、是否需要署名、用途、引入日期。登记表放在本文档末尾，或单独的 `docs/ASSET_LICENSES.md`（引入第一个外部资源时创建）。
4. **AI 生成的美术资源**：引入前必须与用户沟通，并记录生成工具及其使用条款。
5. **引入任何外部工具、插件或资源包之前，先与用户沟通**（任务约束）。
