# 游戏设计文档（GDD）— 机甲乱斗 Mech Brawl

> 状态：阶段 1 文档补写（2026-11-19）。文中所有数值都是**原型值，待测试**；具体数值不在这里重复，见 [MOVEMENT_PARAMETERS.md](MOVEMENT_PARAMETERS.md) 和 [COMBAT_PARAMETERS.md](COMBAT_PARAMETERS.md)。
> 规范来源：[AGENT.md](../AGENT.md)。本文与 AGENT.md 冲突时，以 AGENT.md 为准。

## 1. 愿景

一款原创的第三人称 3D 机甲竞技动作游戏。四台来自完全不同文明的机甲在可破坏的立体战场上展开 1v1 到 1v3 的对决。玩家要读懂对手的预兆，管理能量和位置，用自己机体的强项去打对方的弱点。

### 设计支柱

| 支柱 | 含义 | 不做什么 |
|---|---|---|
| **机甲个性** | 四台机甲在外形、武装、运动方式、资源机制和获胜方式上都不同，背景要体现在玩法里 | 不做统一模型换色，不只靠伤害和血量区分 |
| **立体机动** | Ground-Air Hybrid：地面、起跳、推进、有限悬浮、空中冲刺，受 EN 和高度约束 | 不做无限自由飞行，不允许无限滞空 |
| **战术博弈** | 预兆与反制、招架与诱骗、距离与掩体、能量与时机；每个强项都有反制手段 | 不做无法应对的攻击，不做永久安全位置 |
| **打击感** | 命中、格挡、招架、破防清晰可辨；顿帧、击退、受击动作、音画反馈分层 | 不靠过长硬直或过度震屏制造“力量感” |
| **可交互战场** | 可破坏结构会改变视线、路线和战术；道具在合理位置刷新 | 不做纯装饰的破坏，不做实时网格切割 |

## 2. 核心循环

```
 读局势（目标、高度、EN、掩体、对方大招状态）
   → 选择接近 / 拉扯 / 布阵 / 狙击
   → 出招或防守（预兆 ↔ 反制）
   → 命中确认（打击反馈）→ 追击或撤离
   → 资源恢复（落地回 EN、拾取道具）
   → 局势变化（破坏结构、低血量大招、第三方介入）→ 回到开头
```

一局的节奏：开局抢位置 → 中段消耗、利用场景破坏 → 残局有一方进入低血量，触发特色大招，形成翻盘博弈。

## 3. 模式

两种模式共用同一套战斗内核，只通过 MatchRules 和 AI 战术策略区分（AGENT.md §3），不开发两套战斗系统。

| | 自由乱斗（FREE_FOR_ALL） | 敌方联盟围攻（PLAYER_VS_ALLIANCE） |
|---|---|---|
| 阵营 | 每台机体各自为阵营，互相敌对 | 玩家独立阵营，所有 AI 同阵营 |
| AI 目标选择 | 根据距离、射程、威胁、受击记录、可达性动态选择；不默认针对玩家；有目标粘性和重新评估间隔 | 共同攻击玩家；动态分配主攻 / 牵制 / 机动角色；包抄、保持射程、建立阵地 |
| 友军伤害 | 不存在友军 | 禁止误伤，范围攻击也不例外 |
| 公平约束 | — | 同时高压进攻最多 2 台、同时释放强控最多 1 台（进攻额度）；连续硬控保护 |
| 胜负 | 最后存活者获胜；玩家死亡后可以观战或退出 | 玩家击败所有 AI 获胜；玩家死亡立即失败 |

通用规则：
- 每局 1 名玩家加 1–3 名 AI，AI 从玩家没选的机体中挑选，不重复。
- 每人一条命，首版不复活。
- AI 难度（简单、标准、困难）只影响反应、瞄准、判断和攻击欲望，不提高 HP 或伤害。
- 共 4 × 7 × 3 × 2 = **168 种基础对战配置**：4 台玩家机体 × 7 种敌人组合（剩余 3 台中选 1–3 台）× 3 张地图 × 2 种模式。

练习模式（原型期已实现）：不会阵亡、大招不限次数、陪练机按固定节奏出招，用于熟悉操作。它只存在于场景层，不属于比赛规则。

## 6. 系统概览

### 6.1 Ground-Air 机动与 EN

- **状态**：GROUNDED、GROUND_DASH、TAKEOFF、AIRBORNE、HOVER、AIR_DASH、FALLING、LANDING。
- **方向**：移动方向以镜头的水平朝向为准；垂直推进单独控制；机体朝向可以与移动方向分离，便于锁定侧移和空中射击。
- **EN**：冲刺和悬停都消耗共享 EN，空中不恢复，落地后经过延迟再恢复。EN 耗尽后进入重力下降，保留有限的空中控制，**不能无限滞空**。
- **高度**：主动升空上限为起飞点上方约 10 m，同时受地图绝对天花板约束。
- **机体差异**：通过 MechMovementProfile 配置速度、惯性、悬停消耗等。
- 参数和实测数据见 [MOVEMENT_PARAMETERS.md](MOVEMENT_PARAMETERS.md)，设计决策见 [ARCHITECTURE.md](ARCHITECTURE.md) D-01–D-14。

### 6.2 战斗内核

- **招式**：数据驱动（AttackDefinition），包括前摇 / 活动 / 收招、取消窗口、连段接续、输入缓冲，以及突进的水平转向和有限垂直追踪。
- **判定与结算**：Hitbox 扫掠、Hurtbox、弹丸射线；伤害统一由 DamageSystem 结算，顺序为：伤害权限 → 招架 → 格挡 → 命中。
- **防御**：
  - 格挡覆盖正面扇形，减伤并消耗 EN，EN 不足时破防。
  - 招架有判定窗口，招架失误有惩罚。
  - 白祷的镜盾招架：近战使对方失衡并获得反击窗口；弹丸被折射并转移归属。
  - 光束、爆炸、抓取不可招架；抓取也不可格挡。
- **受击**：个体顿帧（只作用于当事双方）、硬直、失衡、击退；空中受击同样生效。
- **连续硬控保护**：所有硬控共享递减计数，到一定次数后短暂免控，防止 1v3 中被永久控制。
- **混战规则**：
  - 防御只覆盖正面，被包抄是天然的反制。
  - 第三方可以在别人顿帧时插手。
  - 一次招架窗口内只有第一个近战攻击者会失衡。
  - 折射弹按新归属判断伤害权限。
- **权限接口**：`is_hostile`、`can_damage`、`get_valid_targets` 统一由 TeamRules 提供，武器和技能不自行判断阵营。
- 数值见 [COMBAT_PARAMETERS.md](COMBAT_PARAMETERS.md)，决策见 ARCHITECTURE.md D-15–D-28。

### 6.3 低血量特色大招（UltimateSystem）

每台机体有一个体现背景的翻盘手段，统一接入 UltimateSystem 框架：

- **流程**：未解锁（LOCKED）→ HP 低于阈值时就绪（READY）→ 前摇（WINDUP）→ 生效状态（白祷为 JUDGMENT）→ 过载代价（OVERLOAD）→ 用尽（SPENT）。前摇被打断后进入冷却（COOLDOWN），之后可再次发动。
- **设计约束**（四台机体通用）：
  - **有预兆**：所有人都能看到解锁和发动。
  - **可反制**：前摇可以被打断，或者效果可以被规避或熬过。
  - **有代价**：结束后有一段明显的破绽期。
  - **双向博弈**：生效期间对手有多种应对选择，但不能只靠“站远等结束”白拿时间（白祷审判状态的教训，见 MECH_DESIGN.md）。
  - **体现背景**：大招的叙事和视觉表现要与机体来历一致。
- 比赛中每局限用 1 次（可配置）；练习模式不限次数。

### 6.4 破坏与道具（阶段 6）

- 可破坏物有独立的耐久和破坏状态，破坏后必须实际影响遮挡、移动路线或战术选择。
- 优先使用预制的破坏状态、碎块、粒子和音效。
- 结构被破坏后，相关的导航连接失效，AI 必须重新规划路线。
- 随机掉落修复包、能量补给和短时护盾；掉落概率可配置，不会无限堆积，也不会生成在无法到达的地方。

## 7. 操作方案（键鼠优先）

完整按键表见 [README.md](../README.md)。主要按键：

| 类别 | 按键 |
|---|---|
| 移动 | WASD；`Space` 跳跃 / 按住上升；`C` / `Ctrl` 下降；`Shift` 冲刺 |
| 镜头 | 鼠标；`Q` / 中键锁定；`E` / `R` / 滚轮切换目标；`Z` 镜头距离 |

## 8. HUD

- **玩家**：HP、EN、大招状态（未解锁 / 就绪 / 生效倒计时 / 过载 / 冷却）。
- **锁定目标**：名称、HP、当前状态，以及是否处于大招状态。
- **提示文字**：招架、折射、破防、反击、对方冠冕亮起或进入审判等。
- **离屏敌人提示**：屏幕边缘的箭头，附带距离和高度方向（▲▼）。
- **调试面板（F1）**：运动 / 战斗状态、速度、碰撞、修正器、伤害日志、FPS。
- 正式版 HUD 风格见 [ART_BIBLE.md](ART_BIBLE.md) §6。

## 9. AI 原则（阶段 4–5）

- AI 与玩家遵守相同的技能、资源、碰撞和状态机规则，最终都通过共享的 MechMotor 和 CombatStateMachine 执行。
- 禁止预知玩家输入、无视冷却、瞬间精准转向、无条件命中、作弊式空中追踪。
- 混合导航：GroundNavigation、AirRoutePlanner、TransitionPlanner、LocalAvoidance；场景破坏后必须重新规划，并具备导航失败的恢复机制。
- AI 应考虑对方的大招状态，例如不正面冲进白祷的审判状态。
- 调试信息至少包括：目标与评分、行为状态、战术角色、进攻额度、冷却与资源、导航状态和决策原因。
